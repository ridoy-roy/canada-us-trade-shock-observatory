# Project launch checklist

## Before making the repository public

- Read the six-page report once and confirm every statement is understood.
- Confirm the repository still contains no `.env`, raw API responses, or API
  credentials.
- Confirm all automated tests and release-hash verification pass.
- Review the LinkedIn post and résumé entry in the `reports` folder.
- Prepare one report image for the LinkedIn post, preferably the cover or the
  full-scope results page.

## GitHub release

- Change repository visibility only when ready to launch.
- Add the repository description from `PUBLISHING.md`.
- Create release `v0.1.0` and attach the final PDF.
- Confirm the README image and PDF link work while signed out of GitHub.

## LinkedIn launch

- Publish the prepared post after the repository is public.
- Attach one or two readable report images; do not upload screenshots with tiny
  text.
- Add the GitHub project to the LinkedIn Featured section.
- Add the concise project entry to the Projects section or résumé.

## After publication

- Respond to questions using the interview talking points.
- Record feedback separately instead of immediately changing the published
  release.
- Plan comparison-country or comparison-product analysis as a later version.
